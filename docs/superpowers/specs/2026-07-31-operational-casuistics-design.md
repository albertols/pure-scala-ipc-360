## 1. Goal & context

Tab 3 (ETL Operational Table Relationships) rewires from `OPERATIONAL_CARDS` mock to
the real relationships graph + operational job history, and the mock data grows a
**`m_CAS_*` casuistics family** so every relationship shape (1→1, 1→N, N→1, N→N,
multi-layer chains, diamond, fan-in/out, lookups, cross-layer skip) exists end-to-end:
IPC XML → recipe → `statements.sql` row → 14-day `b15*.csv` history — generated by a
NEW reusable generator + committed project skill.

Existing data layer (already gated): `RelationshipService.graph()` builds
`{nodes[recipe|table], edges[source|lookup|writes], meta}` from `LayerToLayerService`
(`statements.sql` tokenizer, 8 layer dirs) + `CorpusService`;
`OperationalService` serves 14 date dirs of
`b15_application_end_with_recipe_null_status.csv` (columns: `cluster_name,
recipe_filename, job_id, app_start_iso, avg_job_duration_in_mins_sec, status,
message`), raw passthrough, joined to relationships only by `recipe_filename` string.

## 3. CAS family (~12 mappings, all 8 layers)

Naming: `m_CAS_<LAYER>_<SHAPE>` mappings, `CAS_*` table names, `wf_CAS_*` workflows —
distinct from SYN (which stays the untouched simple baseline). Shape matrix (each row
= mapping + recipe + L2L row(s) + b15 rows; exact fields kept small, SYN-template
idiom):

| # | Mapping (layer) | Casuistic it pins |
|---|---|---|
| 1 | `m_CAS_STG_L_EVENTS_LOAD` (STG) | chain head, 1→1 |
| 2 | `m_CAS_STG_L_REFS_LOAD` (STG) | second chain head (for diamond) |
| 3 | `m_CAS_ODS_EVENTS` (ODS) | 1→1 link, lookup edge (`CAS_LKP_STATUS`) |
| 4 | `m_CAS_ODS_EVENTS_ENRICH` (ODS) | **N→1 fan-in**: second recipe writing `CAS_ODS_EVENTS` (APPEND) |
| 5 | `m_CAS_DWH_EVENTS_FACT` (DWH) | **N→1 sources**: reads `CAS_ODS_EVENTS` + `CAS_ODS_REFS` (diamond converge) |
| 6 | `m_CAS_ODS_REFS` (ODS) | diamond left leg from `CAS_STG_L_REFS` |
| 7 | `m_CAS_ETL_EVENTS_SPLIT` (ETL) | **1→N**: two targets `CAS_ETL_EVENTS_CURR` + `CAS_ETL_EVENTS_HIST` |
| 8 | `m_CAS_CDM_EVENTS_MART` (CDM) | chain continuation, **N→N**: 2 sources → 2 targets |
| 9 | `m_CAS_RDM_EVENTS_EXPORT` (RDM) | chain, **cross-layer skip source** (reads `CAS_ODS_EVENTS` directly) |
| 10 | `m_CAS_QDM_EVENTS_QUALITY` (QDM) | QDM branch, `.XML` uppercase extension |
| 11 | `m_CAS_OUT_EVENTS_FEED` (OUTPUT) | chain tail ⇒ **≥6-hop end-to-end path** STG→ODS→DWH→CDM→RDM→OUTPUT |
| 12 | `m_CAS_DWH_ORPHAN_METRICS` (DWH) | recipe with NO downstream consumer (leaf table) + table `CAS_STG_UNREFERENCED` appearing only as a source (no writer) — degenerate nodes |

b15 rows: every CAS recipe × all 14 dates; deterministic pattern with variety — at
least one recipe with intermittent `KO` (e.g. #5 fails 3 of 14 days with `message`),
one always-KO day cluster, duration values spread (for avg/p50/p95 to differ),
plus rows for the SYN family exactly as today (untouched).

## 4. Generator + reusable skill (`mock-etl-data`)

- `scripts/mock_etl_data.mts` (Node ≥22.6): input = a JSON **manifest**
  (`scripts/mock_etl_data.manifest.json`, the CAS matrix above as data: mappings,
  layers, fields, sources, targets, lookups, writeMode, partition, failure pattern).
  Output modes: `--emit xml` (renders IPC Powermart XML from the SYN template
  structure), `--emit l2l` (statements.sql rows appended idempotently, marker-comment
  delimited), `--emit b15` (per-date CSV rows appended idempotently), `--check`
  (verifies manifest ↔ corpus ↔ mock consistency, exit 1 on drift).
- **Recipes are generated by the real parser** (byte-faithful): temp-copy pattern only
  (`make regen-corpus` idiom — never in-place; a make target `cas-gen` orchestrates:
  render XMLs → temp copy → parser run → move outputs next to XMLs). CAS XMLs live
  under `parser/src/main/resources/xmltobq/<LAYER>/` like SYN.
- Project skill `.claude/skills/mock-etl-data/SKILL.md` (committed): when to use, the
  manifest schema, the emit/check workflow, corpus-safety rules, how to extend with new
  casuistics. Written per superpowers:writing-skills conventions.

## 5. Backend: operational summary endpoint (read-only)

`GET /api/operational/summary` → `OperationalSummaryDto`:

```
{ dates: [...], recipes: [ { recipeFilename, layer, latestDate, latestStatus,
    okCount, koCount, history: [{date, status, durationMin}],
    avgDurationMin, p50DurationMin, p95DurationMin,
    lastJobId, lastClusterName } ] }
```

Computed in `OperationalService` from all date dirs (mode-aware real/mock, same
resolution as today); layer resolved via `LayerToLayerService` join on
`recipe_filename` ⇒ `recipe`; recipes present in b15 but absent from L2L still appear
(layer `UNKNOWN`) — contract-tested. Percentiles = nearest-rank. No behavior change to
existing endpoints.

## 6. Tab 3 rewiring (frontend)

- Data: `useRelationships()` + new `useOperationalSummary()` + existing
  `useOperationalDates`/`useOperational(date)`; mock `OPERATIONAL_CARDS` retired from
  Tab 3 (mockData ledger updated; export deleted if Tab 4 doesn't import it — verify).

- Cards keep the EXISTING `OperationalCard` visuals: status dot, layer badge, counts,
  avg/p50/p95 row, OK/KO history strip (14 cells), `job_id`/cluster link-outs (GCP URL
  templates). Filters (layer/kind/status chips) and search operate on real data;
  zoom/collapse compact pills unchanged.
- Selection side panel: real related-cards list (graph neighbors), GCP quick links.
- **Preview overlay** (user ask "hover full window"): clicking a recipe card's preview
  affordance (and table card ⇒ its writer recipe) opens a full-window modal overlay

  recipe via `recipeToCanvas` (from sub-project 3, post-merge base) + a Raw JSON pane
  with CopyButton. XML-side fallback: if the recipe file is missing, show the mapping's
  model canvas via `toCanvas` instead.

## 7. Gates & testing

- **TDD throughout.** Backend: MockMvc for summary (aggregates, UNKNOWN layer,
  percentile math, mode). Generator: `--check` self-verification + unit test on
  manifest rendering determinism. Frontend: RTL+MSW — graph renders CAS+SYN nodes,
  TimePicker changes card states, filters, preview overlay opens with canvas + raw
  JSON.
- **`scripts/relationships_sweep.mts`**: fetches `/api/relationships` +
  `/api/operational/summary`; asserts each casuistic structurally: a table with ≥2
  writer recipes; a recipe with ≥2 write targets; a source-only table; a
  consumer-less recipe; a lookup edge; a ≥6-hop STG→OUTPUT path; the diamond (two
  disjoint paths STG_L_REFS/STG_L_EVENTS → DWH_EVENTS_FACT); a KO recipe on the anchor
  date; every CAS recipe has 14 history entries. Wired into `validate_loop.sh`.
- **Floor raises** (this stream only): mappings 69→81, recipes 74→86, L2L entries
  18→31 (12 CAS mappings; #7 contributes an extra multi-target row shape) — exact
  numbers pinned by the plan after generation; `CorpusContractTest`,
  `viewer_sweep.mts`, `LayerToLayerContractTest` updated in the SAME task that adds
  the data (CAS XMLs must also pass the Tab-1 viewer sweep — free cross-gate).
- Visual contract: Tab 3 keeps its prototype look — data swap + sanctioned additions
  only (preview overlay, real TimePicker dates).

## 8. Acceptance criteria

1. Tab 3 renders the real graph: every SYN + CAS recipe/table appears; filters,
   search, zoom/collapse, selection panel all work on real data.
2. TimePicker walks the 14 mock dates; card states/history match the CSVs (spot-check
   the KO pattern).
3. Preview overlay: recipe card → visual canvas + raw JSON; table card → writer
   recipe; Esc closes; Tab 1/2 untouched by the overlay.
4. `relationships_sweep` green inside `make validate-loop` (all casuistics asserted).
5. `viewer_sweep` 81/81 — every CAS XML renders in Tab 1 too.
6. Full suite green: `pnpm test`, `tsc`, `make test`, `make check`,
   `make validate-loop`.
7. `mock-etl-data` skill committed and its `--check` mode passes on the shipped
   corpus; re-running emit modes is idempotent (no duplicate rows).
8. Docs updated (architecture.md summary endpoint + Tab 3 line, frontend/AGENTS.md
   ledger, CLAUDE.md corpus caveats CAS note, ADR if any new decision emerges).
