# Synthetic Operational Data & Loop-Validation Harness — Design

**Sub-project:** 4 of 6 (see Foundation spec §1 Roadmap) — `docs/superpowers/specs/2026-07-29-etl360-foundation-design.md`
**Branch:** `feat/etl360-synthetic-operational` (stacked on `feat/etl360-foundation`, PR #1)
**Source requirements:** `first_prompt.md` §Tab-3 approach, §HOW-TO-RUN 3–5, §MORE-ACTIONS (harness)
**Approved:** 2026-07-30 (design presented and approved in-session)

## 1. Goal

Give the ETL 360 suite its operational data spine — entirely mock/synthetic, entirely
committed — and prove the frontend → middleware → backend loop end-to-end with an
automated harness. Zero GUI changes: Tab 3's graph/cards/TimePicker (sub-project 5)
consume this later. Deliverables:

1. A **synthetic mapping family** in the corpus (real parser-generated recipes/DDLs).
2. A **mock `statements.sql` mirror** (SCALAMATICA_LAYER_TO_LAYER_CONFIG rows).
3. A **b15 operational CSV history** (14 dated snapshots) plus its deterministic generator.
4. **Middleware endpoints**: `/api/relationships`, `/api/operational/dates`, `/api/operational/{date}`.
5. **Frontend data layer**: typed hooks only (`useRelationships`, `useOperationalDates`, `useOperational`).
6. The **loop-validation harness**: contract tests + `make validate-loop`.

## 2. Hard rules (inherited + new)

1. All Foundation hard rules hold: Figma visual contract (no GUI changes at all here),
   corpus safety (generation only over temp copies), never commit the real
   `parser/src/main/resources/DWH_CONTROL/`, parser behavior unchanged.
2. Synthetic artifacts are **clearly synthetic**: mapping/table names carry the `SYN`
   marker (`m_SYN_*`, `SYN_*` tables). Never imitate real-looking production identifiers
   (anonymization rule).
3. Mock data lives only under the committed mock mirror
   `backend/src/main/resources/mock/` — never under the git-ignored real roots.
4. Determinism: the b15 generator is seeded; same seed + same inputs ⇒ byte-identical
   CSVs. Committed CSVs are the artifact of record (regenerable, diffable).
5. LayerToLayer ingestion reads **exactly** these eight subdirs of
   `<dwhControl>/LAYER_TO_LAYER/`: `STG, ODS, DWH, CDM, RDM, QDM, ETL, OUTPUT` — any
   other file or subdir is ignored (first_prompt exclusion rule).

## 3. Synthetic mapping family (corpus additions)

Ten hand-authored Powermart XMLs forming one coherent business flow ("SYN orders") that
exercises every relationship shape Tab 5 must render — chain, diamond, shared lookup,
multi-target, cross-layer feed:

| Layer | Mapping | Sources → Target (tables) |
|---|---|---|
| STG | `m_SYN_STG_L_ORDERS_LOAD` | `SYN_FF_ORDERS` (file) → `STG_L_SYN_ORDERS` |
| STG | `m_SYN_STG_L_CUSTOMERS_LOAD` | `SYN_FF_CUSTOMERS` → `STG_L_SYN_CUSTOMERS` |
| ODS | `m_SYN_ODS_ORDERS` | `STG_L_SYN_ORDERS` (+ lookup `SYN_LKP_CURRENCY`) → `ODS_SYN_ORDERS` |
| ODS | `m_SYN_ODS_CUSTOMERS` | `STG_L_SYN_CUSTOMERS` → `ODS_SYN_CUSTOMERS` |
| DWH | `m_SYN_DWH_ORDERS_FACT` | `ODS_SYN_ORDERS` + `ODS_SYN_CUSTOMERS` (diamond join) → `DWH_SYN_ORDERS_FACT` |
| CDM | `m_SYN_DM_ORDERS_SUMMARY` | `DWH_SYN_ORDERS_FACT` (+ lookup `SYN_LKP_CURRENCY`) → `DM_SYN_ORDERS_SUMMARY` |
| RDM | `m_SYN_RDM_ORDERS_EXPORT` | `DM_SYN_ORDERS_SUMMARY` → `RDM_SYN_ORDERS_EXPORT` |
| QDM | `m_SYN_QDM_ORDERS_QUALITY` | `DWH_SYN_ORDERS_FACT` → `QDM_SYN_ORDERS_QUALITY` |
| ETL | `m_SYN_ETL_ORDERS_BRIDGE` | `ODS_SYN_ORDERS` → `ETL_SYN_ORDERS_BRIDGE` (two targets: + `ETL_SYN_ORDERS_AUDIT`) |
| OUTPUT | `m_SYN_OUT_ORDERS_FEED` | `RDM_SYN_ORDERS_EXPORT` → `OUT_SYN_ORDERS_FEED` |

- Each XML is a small valid Powermart document (fixture-corpus shape: SOURCE, TARGET,
  ≥1 TRANSFORMATION with a non-identity EXPRESSION, MAPPING with CONNECTORs) placed at
  `parser/src/main/resources/xmltobq/<LAYER>/m_SYN_*.xml`. At least one uses the
  uppercase `.XML` extension (locks in the 59-XML case-insensitivity fix).
- Recipes + DDL JSONs are generated by the **real parser over a temp copy** and the
  outputs committed next to the XMLs (standard corpus layout). No hand-written recipes.
- Corpus contract test floors rise: ≥69 mappings, ≥74 recipes (current 59/64 + 10).
  The expressions archive gains the synthetic formulas (they carry the `SYN` marker).

## 4. Mock statements.sql (LayerToLayerConfig)

Files: `backend/src/main/resources/mock/DWH_CONTROL/LAYER_TO_LAYER/<LAYER>/statements.sql`
for the eight layers of §2.5. Content: `INSERT INTO CONTROL.SCALAMATICA_LAYER_TO_LAYER_CONFIG
VALUES (...)` rows exactly in the first_prompt shape — columns:

`layer, mapping_xml_dir, recipe, workflow, target, execution_order, sources[] STRUCT(table, active, day_offset), lookup_tables[], targets_write_mode[] STRUCT(target_table, write_mode), target_partition[] STRUCT(target_table, partition_type, partition_key, subpartition_key)`

- One row per synthetic mapping (10 rows across the eight files) **plus** ~8 rows
  referencing existing real anonymized corpus mappings (CDM/DWH/ODS picks whose
  `_ETL_*.json` recipes exist) so the graph spans the real corpus too.
- Realistic variety: execution orders forming the chain, `day_offset` 0/±1/30, inactive
  sources, `ORPHAN_WRITE_MODES`/`TRUNCATE_INSERT`/`APPEND` write modes, `DAILY`/`MONTHLY`/
  `UNKNOWN_PARTITION_TYPE` partitions, empty and non-empty `lookup_tables`.
- A decoy file outside the eight dirs (e.g. `LAYER_TO_LAYER/ARCHIVE/statements.sql`)
  is committed to prove the exclusion rule (tests assert it is ignored).

**Ingestion.** `LayerToLayerService` (backend) parses the eight files into
`List<LayerToLayerEntryDto>` with a purpose-built parser for this fixed statement shape
(multi-line tolerant; STRUCT arrays; quoted strings). Malformed row ⇒ WARN log + skip
(ExpressionService precedent: one bad row must not empty the config); skipped-row count
is surfaced in the relationships payload meta. Cache: single mtime-of-newest-file key,
DomService idiom. `DataRoots.dwhControl()` supplies the root (real dir wins over mock —
unchanged Foundation fallback).

## 5. b15 operational CSV history + generator

**Layout.** `backend/src/main/resources/mock/composer/dwh/config/cluster_tuning/inputs/<YYYY_MM_DD>/b15_application_end_with_recipe_null_status.csv`
— 14 consecutive daily snapshots at fixed anchor dates `2026_07_16 … 2026_07_29`
(fixed, not "today": determinism). Columns exactly:

`cluster_name, recipe_filename, job_id, app_start_iso, avg_job_duration_in_mins_sec, status, message`

- Rows cover every recipe named in the LayerToLayerConfig mock (synthetic + real picks).
- Scenario mix per the first_prompt: `SUCCESS`, `FAILED` (with message), **null/empty
  status** (the b15 query's main investigation case), duration spread (seconds to >1h,
  `"74m 40sec"` format), stable-but-varying `cluster_name`/`job_id` shaped like the log
  examples (`cluster-wf-…`, `application_<epoch>_<seq>`), day-over-day evolution so
  Tab 5's sparklines/timeline have real signal (a recipe that flips SUCCESS→FAILED→SUCCESS,
  one that disappears for two days, one always-null).
- **Generator:** `scripts/gen_b15_history.py` (stdlib-only Python 3), committed. Inputs:
  seed, anchor date, day count, the mock LayerToLayerConfig (it reads recipe names from
  the statements.sql files). Same inputs ⇒ byte-identical output. Regenerating with a
  later anchor extends the timeline (documented in the script header and README).

**DataRoots change.** `composer()` gains the mock tier: real dir → `"real"`, else
`mockRoot/composer` if present → `"mock"`, else `"absent"` (exactly the dwhControl
pattern; ADR-0003 consequence updated — its "no mock tier for composer in Foundation"
was Foundation-scoped by design).

## 6. Middleware endpoints

All GET, problem+json errors, OpenAPI-documented (springdoc picks them up as usual):

| Endpoint | Returns |
|---|---|
| `/api/relationships` | `RelationshipsDto { nodes: [NodeDto], edges: [EdgeDto], meta: { entryCount, skippedRows, layers } }` |
| `/api/operational/dates` | sorted list of available `YYYY-MM-DD` (from `YYYY_MM_DD` dirs) + `mode` (`real\|mock\|absent`) |
| `/api/operational/{date}` | `OperationalSnapshotDto { date, rows: [B15RowDto] }` — accepts `YYYY-MM-DD` |

- `NodeDto { id, kind: "table"|"recipe", name, layer, mappingPath?, hasRecipe?, workflow?, executionOrder?, writeMode?, partitionType? }`;
  `EdgeDto { from, to, kind: "source"|"lookup"|"writes" }`. A recipe node links its source
  tables (`source` edges in), lookup tables (`lookup` edges in), and target tables
  (`writes` edges out). Node ids are stable strings (`table:<NAME>` / `recipe:<FILE>`),
  so sub-project 5 can diff/persist selections.
- Missing date dir ⇒ **404 problem+json** whose `detail` carries the first_prompt-mandated
  operator message: `"No operational snapshot for <date> — b15 CSV not present under
  inputs/<YYYY_MM_DD>/"` plus the nearest available date. Malformed date string ⇒ 400.
- `composerMode` joins `/api/health` and `/api/config` payloads (mode surfacing
  precedent from Task 8).
- GCP deep links stay a frontend concern: `/api/config` already serves the URL templates
  (`dataprocJobUrl`, `dataprocClusterUrl`, `loggingUrl`); B15RowDto ships the raw
  `cluster_name`/`job_id` for Tab 5 to compose links (no backend URL building).

## 7. Frontend data layer (no GUI)

- Regenerate `types.gen.ts` from the live backend (existing `make generate-api` flow).
- `queries.ts` gains `useRelationships()`, `useOperationalDates()`, `useOperational(date)`
  (+ type aliases `RelationshipGraph`, `OperationalSnapshot`, `B15Row`), same
  `staleTime` conventions.
- MSW hook tests per the Task 11 pattern. No component file is touched.

## 8. Loop-validation harness

1. **Backend contract tests** (JUnit, the CorpusContractTest pattern):
   - `LayerToLayerContractTest`: parses all eight mock files; asserts every referenced
     `recipe` exists in the corpus (`CorpusService.allRecipePaths`), every synthetic
     mapping appears, the decoy dir is excluded, skippedRows == 0.
   - `OperationalContractTest`: all 14 committed date dirs parse; every
     `recipe_filename` appears in LayerToLayerConfig; `/api/operational/{date}` 200 for
     each; a known-absent date 404s with the operator message; `/api/relationships`
     serves ≥ (10 synthetic + 8 real) recipe nodes with consistent edges (no edge
     endpoint missing from nodes).
2. **`make validate-loop`**: boots the backend (install-then-run pattern), curls the
   three new endpoints plus `/api/health` (asserting `composerMode: "mock"`,
   `dwhControlMode: "mock"` in the default checkout), runs `cd frontend && pnpm test`
   (MSW hook tests), tears down, exits non-zero on any failure. This is the
   frontend → middleware → backend loop gate the harness ask names.
3. **Docs/practices**: new ADR `0006-synthetic-operational-data.md` (mock-mirror tiers,
   determinism rule, SYN naming); `.claude/skills/validate-loop/SKILL.md` thin wrapper;
   CLAUDE.md + architecture.md endpoint table updates; b15 generator usage in README.

## 9. Testing strategy

TDD per task: parser unit tests (statement tokenizer edge cases: multi-line, STRUCT
nesting, quoted commas, malformed row skip), DataRoots composer-tier unit tests
(real/mock/absent ×3), service tests over a fixture mirror (tiny statements.sql +
2-day CSV history under `backend/src/test/resources/`), MockMvc slice tests for the
three endpoints (200/400/404 shapes), the two contract tests over the real mock data,
frontend hook tests (MSW). The corpus contract floors (≥69/≥74) re-certify the
synthetic additions end-to-end.

## 10. Out of scope

- Any GUI change (Tab 3 graph/cards/TimePicker = sub-project 5; Viewer/Modifier = 2/3).
- Derived stats endpoints (p50/p95/p99, sparkline aggregation) — sub-project 5 decides
  whether they're computed client-side from `/api/operational/{date}` history or get a
  backend aggregate; raw rows ship now.
- Real GCP ingestion (LogAnalytics), BigQuery/GCS persistence — future LZ work
  (first_prompt §HOW-TO-RUN 5); the layout here is chosen so that swap stays additive
  (real tier already wins over mock in DataRoots).
- Write endpoints of any kind.

## 11. Acceptance criteria

1. `make test` green with raised corpus floors (≥69 mappings, ≥74 recipes).
2. `make validate-loop` green from a fresh checkout (backend boots, three endpoints
   serve mock data, hook tests pass, teardown clean).
3. `/api/relationships` renders the full SYN chain: STG→ODS→DWH→CDM→RDM/QDM plus
   ETL/OUTPUT hops, the diamond join, and the shared lookup — all reachable from nodes.
4. `/api/operational/2026-07-29` serves rows incl. SUCCESS/FAILED/null-status;
   `/api/operational/2026-07-30` 404s with the operator message; `dates` lists 14 days.
5. Regenerating the b15 history with the committed seed reproduces the committed CSVs
   byte-identically.
6. The decoy `LAYER_TO_LAYER/ARCHIVE/statements.sql` provably ignored (test).
7. Docs match reality: ADR-0006 exists, architecture.md endpoint table lists the three
   new endpoints, README documents the generator, skills updated.
